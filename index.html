What is Umbra Link?

Umbra Link is the identity and connection layer that sits under the entire Umbra-Noesis stack. It defines how every person, node, and device is represented, and how those identities connect across:

  • Local-first networks (home labs, boats, cabins, mobile rigs).
  • Home computers, laptops, workstations, and future supported hardware.
  • Selective, consent-based remote links when cloud or WAN is required.

Identity inside the ecosystem

Umbra Link gives each actor in the system a structured identity: User IDs, Node IDs, and eventually Connection Codes that bind them together with a clear trust posture.

User ID

A human-facing identity that defines who the system is working with, not just which machine is active.

Node ID

A unique identity for each Umbra-Noesis node: Genesis, MobileCore, PCe kits, future racks, and remote units.

Connection Code

A personal, shareable code for linking trusted devices and locations into the same private mesh (future feature).

Umbra Link Roadmap (High Level)

  • Identity Schema — formalize User ID and Node ID specs, aligned with AACP for message binding.
  • Connection Codes — one personal code to link home rigs, field units, and future PCe systems into a unified mesh.
  • Mesh Routing & Sync — rules for how nodes discover each other, sync selectively, and stay resilient when offline.

Integration Points

Umbra Link sits underneath and between the rest of the Umbra-Noesis ecosystem:

  • UmbraOS as the platform layer that hosts the link services.
  • EVAA Cognition as the node-level AI that understands who it’s talking to and from which node.
  • PCe Systems as the documented hardware profiles that Umbra Link binds into a single environment.
  • E.V.E. Systems as the UI layer that surfaces identities, sessions, and active links to the human.

This page is an early structural skeleton. Final specs, node-linking behaviors, and public-facing APIs will be defined as Umbra-Noesis approaches external release.
